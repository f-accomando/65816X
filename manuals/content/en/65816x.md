# What 65816X is

65816X is a starting point for an enhanced SNES on a Lattice ECP5 FPGA. It has a 65C816 processor that can run extra instructions, the DMA and the multiplier of the Ricoh 5A22, and a PPU that will later get a 3D pipeline.

## What works today

| Part | State |
|---|---|
| Processor | 53 of 256 opcodes; 47 pass the test bench; no interrupts |
| DMA and math of the 5A22 | general DMA, 8 channels; instant multiply and divide; no HDMA |
| Video | timing and video memory only; no image |
| Audio | 4 communication ports that echo; no sound |
| Memory | 128 KB work RAM; 64 KB ROM |
| Real hardware | never tried |

## Two planned variants

| Variant | FPGA | Idea |
|---|---|---|
| A | ECP5 LFE5U-45F | one processor core, the original audio |
| B | ECP5 LFE5U-85F | two processor cores, a stronger PPU, 16 audio voices |

The numbers of the variants are estimates. Today the design fits only the larger FPGA, because of its block RAM.

::: note
The project runs in simulation and synthesis. There is no board support yet, and the choice of the board is still open.
:::

# How the system is built

The design follows the multi-chip SNES. Each chip is a separate module, and one 8-bit bus connects them.

```
  +---------------------------+
  | s_cpu_5a22                |
  |   cpu65816x      DMA 8ch  |  one 8-bit bus
  |   registers, mul/div      |--+-------+--------+--------+--------+
  +---------------------------+  |       |        |        |        |
                             cart_rom  wram   ppu_stub apu_stub ext_regs
```

## Modules

| Module | File | Job |
|---|---|---|
| Processor | `rtl/cpu65816x.v` | the 65C816 core and the extensions |
| Ricoh 5A22 | `rtl/s_cpu_5a22.v` | registers, multiply, divide, DMA |
| PPU | `rtl/ppu_stub.v` | video timing and video memory |
| Audio | `rtl/apu_stub.v` | 4 ports with echo |
| Work RAM | `rtl/wram.v` | 128 KB with mirrors and a data port |
| Cartridge | `rtl/cart_rom.v` | 64 KB LoROM |
| Extension registers | `rtl/ext_regs.v` | identifier, mode, speed |
| Top | `rtl/snes_plus_top.v` | connects all modules |

## Memory map

The table is valid in banks `$00-$3F` and `$80-$BF`.

| Address | Content |
|---|---|
| `$0000-$1FFF` | mirror of the first 8 KB of the work RAM |
| `$2100-$213F` | PPU registers (video memory: `$2115-$2119`, `$2139-$213A`) |
| `$2140-$217F` | audio ports, repeated every 4 bytes |
| `$2180-$2183` | work RAM port: data and 17-bit address with auto-increment |
| `$4200-$421F` | 5A22 registers: multiply, divide, DMA start, status |
| `$4300-$437F` | DMA registers of each channel |
| `$5F00-$5FFF` | extension registers |
| `$8000-$FFFF` | cartridge ROM |

Banks `$7E-$7F` hold the full work RAM. Banks `$40-$7D` and `$C0-$FF` show the ROM in `$8000-$FFFF`.

## The bus

- A read takes 2 clock cycles. The address is valid in the first, and the data in the second.
- A write takes 1 clock cycle.
- The DMA stops the processor between two instructions and then takes the bus.

# The processor

The core starts in emulation mode, like the real chip. It reads the start address from `$00FFFC`. The M and X flags select 8 or 16 bits for the accumulator and the index registers.

## Instructions that exist today

| Group | Instructions |
|---|---|
| Load and store | `LDA` immediate, absolute, absolute,X, long; `LDX`, `LDY` immediate, absolute; `STA` absolute, absolute,X, long; `STX`, `STY` absolute |
| Arithmetic and logic | `ADC` immediate, absolute; `SBC` immediate; `CMP` immediate, absolute; `AND`, `ORA`, `EOR` immediate |
| Increment | `INC A`, `DEC A`, `INX`, `DEX`, `INY`, `DEY` |
| Transfers | `TAX`, `TXA`, `TAY`, `TYA` |
| Flags and mode | `CLC`, `SEC`, `SEI`, `CLI`, `XCE`, `REP`, `SEP` |
| Jumps | `BRA`, `BNE`, `BEQ`, `BCC`, `BCS`, `BPL`, `BMI`, `JMP`, `JML`, `JSR`, `RTS` |
| Stack | `PHA`, `PLA` |
| Other | `NOP`, `WDM` |

::: warn
The core runs each opcode that is not in this table as `NOP`. A program that uses one gives no error.
:::

## Known differences from the real chip

| Instructions | Difference |
|---|---|
| `JSR`, `RTS`, `PHA`, `PLA` | in emulation mode the stack leaves page 1 |
| `XCE` | the change to emulation mode does not move the stack to page 1 |
| `SEP` and all others | there is no decimal flag, and no decimal mode |
| all, emulation mode | the high byte of the stack pointer is not held at 01 |
| all | the number of clock cycles differs from the real chip |
| interrupts | NMI, IRQ, BRK, and COP do not exist |

# Extensions

The extensions are new operations behind `WDM`, an opcode that the real chip keeps for future use. Original games do not use it.

## Modes

| Value of $5F01 | Mode | What WDM does |
|---|---|---|
| 0 | SNES (after reset) | skips two bytes and does nothing |
| 1 | accelerated | skips two bytes and does nothing |
| 2 | extended | runs the extension |

The register `$5F00` always reads `$58`: use it to detect the extensions.

## Operations

| Code | Name | Effect |
|---|---|---|
| `WDM $01` | MUL | `Y:A = A * X`, unsigned |
| `WDM $02` | DIV | `A = A / X`, `Y` = remainder; with `X` = 0: `A` = `$FFFF`, `Y` = old `A`, V = 1 |
| `WDM $03` | MAC | adds `A * X` to a 32-bit total |
| `WDM $04` | MACRD | reads the total: low half in `A`, high half in `Y` |
| `WDM $05` | MACCLR | sets the total to 0 |

::: warn
Use the extensions with a 16-bit accumulator and 16-bit index registers.
:::

## Try it step by step

::: try
**1.** Switch to native mode with `CLC` and `XCE`.

**2.** Write 2 to `$5F01` with an 8-bit accumulator.

**3.** Select 16 bits with `REP #$30`.

**4.** Load `A` with `$1234` and `X` with `$0010`.

**5.** Use `WDM $01`. You must get `A` = `$2340` and `Y` = `$0001`.
:::

::: copy
        CLC
        XCE                 ; native mode
        SEP #$20
        LDA #$02
        STA $5F01           ; extended mode on
        REP #$30
        LDA #$1234
        LDX #$0010
        WDM $01             ; A = $2340, Y = $0001
:::

# Write a program

`sim/asm.py` is a small assembler for the instructions of the chapter "The processor". It makes a 64 KB image of bank 0.

## Rules of the assembler

- Code starts at `$8000`. Use `.org` to move.
- A label ends with a colon. A comment starts with `;`.
- `.byte` and `.word` write data.
- A number starts with `$` (hexadecimal) or is decimal.
- The size of an immediate value follows the last `REP` or `SEP` above it in the file.
- For `LDA` and `STA`, a hexadecimal address with more than 4 digits gives a long address.
- Set the start address at `$FFFC`.

::: warn
An address with `,X` is always 16 bits. The assembler drops the bank of `STA $7E0100,X`.
:::

## Assemble a file

1. Save your program as `my.asm`. Start from the box below.
2. Run the command of the second box. The assembler prints the name of the output file and your labels.

::: copy
        .org $8000
reset:  CLC
        XCE
done:   BRA done

        .org $FFFC
        .word reset
:::

::: copy
python3 sim/asm.py my.asm my.hex
:::

# Test the design

| Command | What it checks |
|---|---|
| `make test` | the full system with the Python simulator |
| `make iverilog` | the same checks with Icarus Verilog |
| `make mutation` | that the tests find faults that a script puts into the design |
| `make unit` | single modules against a reference model |
| `make cpu` | the processor, one instruction at a time |
| `make synth` | synthesis for the FPGA and the resource limits |
| `make manual-check` | that this manual matches the sources |
| `make check` | all of the above |

## Read the processor score

1. Run `make cpu`.
2. Open `build/cpu_score.txt`.
3. Find your opcode in the map: the row is the first digit, the column is the second.

| Sign | Meaning |
|---|---|
| `#` | passes in both modes |
| `n` | passes only in native mode |
| `e` | passes only in emulation mode |
| `!` | does not pass |
| `.` | no test |

## Use the public test vectors

The project SingleStepTests/65816 (MIT license) gives 10,000 tests for each opcode and mode. The files are large, and they stay outside the repository.

1. Get the files from `https://github.com/SingleStepTests/65816`. Put the folder `v1` in a folder next to the repository.
2. Run the reference model check. It must report 0 differences.
3. Run the processor score. It takes some minutes.

::: copy
make ref-public SST=../65816-test-vectors
make cpu-public SST=../65816-test-vectors
:::

| Measured on 2026-11-27 | Result |
|---|---|
| Reference model | 0 differences in 1,030,026 vectors |
| Processor, unchanged vectors | 0 of 256 opcodes; 266,966 of 1,060,000 vectors |
| Processor, diagnosis with `SST_FLAGS="--d0 --page1"` | 47 of 256 opcodes; 523,405 of 529,750 vectors |

The unchanged score is 0 because the decimal flag is missing and the stack pointer is not held in page 1.

| Resource | Measured | Limit of the LFE5U-85F |

| Logic (equivalent LUT4), yosys 0.52 | 4,393 | 83,640 |
| Logic (equivalent LUT4), yosys 0.33 | 12,604 | 83,640 |
| Block RAM | 125 | 208 |

The limits in the table come from the script `syn/budget.py`. They were not checked against the data sheet. The cause of the difference between the two yosys versions is not known.
