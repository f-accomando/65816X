# What 65816X is

65816X is a starting point for an enhanced SNES on a Lattice ECP5 FPGA. It has a 65C816 processor that can run extra instructions. It also has the DMA and the multiplier of the Ricoh 5A22. A later step gives the PPU a 3D pipeline.

## What works today

| Part | State |
|---|---|
| Processor | all 256 opcodes of the 65C816, cycle by cycle, with interrupts and decimal mode |
| DMA and math of the 5A22 | general DMA, 8 channels; multiply and divide with the timing of the original; no HDMA |
| Video | SNES timing, all registers and video memories; backgrounds of the modes 0 and 1 |
| Audio | 4 communication ports that echo; no sound |
| Memory | 128 KB work RAM; 64 KB ROM |
| Real hardware | never tried |

## The target FPGA

The target is the Lattice ECP5 LFE5U-85F. The enhanced machine adds a second processor, a stronger video part, and 16 audio voices. Those parts are not built yet. A larger FPGA, the Lattice Certus-N2 CT20, is a future target for the enhanced machine without compromises.

::: note
The project runs in simulation and synthesis. There is no board support yet, and the choice of the board is still open.
:::

# How the system is built

The design follows the multi-chip SNES. Each chip is a separate module, and one 8-bit bus connects them.

```
  +---------------------------+
  | s_cpu_5a22                |
  |   c816_core      DMA 8ch  |  one 8-bit bus
  |   registers, mul/div      |--+-------+--------+--------+--------+
  +---------------------------+  |       |        |        |        |
                             cart_rom  wram   ppu_top  apu_stub ext_regs
```

## Modules

| Module | File | Job |
|---|---|---|
| Processor | `rtl/cpu/` | the 65C816 core and the extensions |
| Ricoh 5A22 | `rtl/s_cpu_5a22.v` | registers, multiply, divide, DMA |
| PPU | `rtl/ppu/` | video timing, registers, video memories, pixels |
| Audio | `rtl/apu_stub.v` | 4 ports with echo |
| Work RAM | `rtl/wram.v` | 128 KB with mirrors and a data port |
| Cartridge | `rtl/cart_rom.v` | 64 KB LoROM |
| Extension registers | `rtl/ext_regs.v` | identifier, mode, speed |
| Top | `rtl/snes_plus_top.v` | connects all modules |

## Memory map

The table is valid in banks `$00-$3F` and `$80-$BF`.

| Address | Content |
|---|---|
| `$0000-$1FFF` | mirror of the first 8 KB of the work RAM |
| `$2100-$213F` | PPU registers: all are present; most have no visible effect yet |
| `$2140-$217F` | audio ports, repeated every 4 bytes |
| `$2180-$2183` | work RAM port: data and 17-bit address with auto-increment |
| `$4200-$421F` | 5A22 registers: multiply, divide, DMA start, status |
| `$4300-$437F` | DMA registers of each channel |
| `$5F00-$5FFF` | extension registers |
| `$8000-$FFFF` | cartridge ROM |

Banks `$7E-$7F` hold the full work RAM. Banks `$40-$7D` and `$C0-$FF` show the ROM in `$8000-$FFFF`.

## The bus

- One processor cycle takes 2 cycles of the FPGA clock.
- In the first one, the address is valid and a read or a write starts. In the second one, read data arrives.
- The DMA stops the processor at the next processor cycle and then takes the bus.

## Video timing

The video part counts the time as the SNES does. The system uses the NTSC values.

| Item | NTSC | PAL |
|---|---|---|
| Master clocks in a dot | 4 (two dots of a line take 6) | the same |
| Master clocks in a line | 1364 | 1364 |
| Lines in a frame | 262 | 312 |
| First line of the vertical blank | 225 (240 with overscan) | the same |

Interlace adds one line to each second frame. One line in some frames is 4 master clocks shorter (NTSC) or longer (PAL). In simulation, one FPGA clock is one master clock. Thus a frame takes about 357,000 clocks.

## Video memory

Write and read the video memory in a blank period. The screen is off (`$2100` bit 7), or the vertical blank runs.

1. Write `$80` to `$2115`. The address then advances after the high byte.
2. Write the word address to `$2116` and `$2117`.
3. To write, store the low byte to `$2118` and the high byte to `$2119`.
4. To read, set the address again. Read `$2139` and then `$213A`: this is one pair.
5. Discard the first pair. The next pairs give the words from the start address.

::: warn
A write to the video memory while the picture is drawn is lost, as on the real console.
:::

## The first picture

The video part draws the backgrounds of the modes 0 and 1 today. The simplest picture is the backdrop: the colour 0 of the colour memory.

| Register | Content |
|---|---|
| `$2100` | bit 7: black screen (the value after reset); bits 3-0: brightness, 0 to 15 |
| `$2121` | number of the colour to write |
| `$2122` | the colour: first the low byte, then the high byte |

A colour has 15 bits: 5 for blue, 5 for green, 5 for red. This code shows an orange screen.

::: copy
        SEP #$20
        LDA #$00
        STA $2121           ; colour 0: the backdrop
        LDA #$1F
        STA $2122           ; low byte
        LDA #$02
        STA $2122           ; high byte: colour $021F
        LDA #$0F
        STA $2100           ; full brightness, screen on
:::

1. Run `make ppu`. It compares the video part with a reference model.

The core starts in emulation mode, like the real chip. It reads the start address from `$00FFFC`. The M and X flags select 8 or 16 bits for the accumulator and the index registers.

| Source | Native vector | Emulation vector | Taken when |
|---|---|---|---|
| NMI | `$00FFEA` | `$00FFFA` | its input rises |

# Multiply and divide

The Ricoh 5A22 has a multiplier and a divider. A program writes the numbers into registers, waits, and reads the result.

| Operation | Write | Wait | Read |
|---|---|---|---|
| 8 x 8 bits | `$4202`, then `$4203` | 8 processor cycles | product in `$4216-$4217` |
| 16 / 8 bits | `$4204-$4205`, then `$4206` | 16 processor cycles | quotient in `$4214-$4215`, remainder in `$4216-$4217` |

A division by 0 gives the quotient `$FFFF`. The remainder is the dividend.

::: try
**1.** Select an 8-bit accumulator with `SEP #$20`.

**2.** Load 7 and write it to `$4202`.

**3.** Load 9 and write it to `$4203`.

**4.** Run three `NOP` instructions.

**5.** Read `$4216`. You must get `$3F`.
:::

::: warn
A read that comes too soon gives a partial value, as on the real console.
:::

# Extensions

The extensions are new operations behind `WDM`, an opcode that the real chip keeps for future use. Original games do not use it.

## Modes

| Value of $5F01 | Mode | What WDM does |
|---|---|---|
| 0 | SNES (after reset) | skips two bytes and does nothing |
| 1 | accelerated | skips two bytes and does nothing |
| 2 | extended | runs the extension, in native mode of the processor |

In emulation mode, `WDM` does nothing, also with the value 2.

The register `$5F00` always reads `$58`: use it to detect the extensions.

## Operations

| Code | Name | Effect |
|---|---|---|
| `WDM $01` | MUL | `Y:A = A * X`, unsigned |
| `WDM $02` | DIV | `A = A / X`, `Y` = remainder; with `X` = 0: `A` = `$FFFF`, `Y` = old `A`, V = 1 |
| `WDM $03` | MAC | adds `A * X` to a 32-bit total |
| `WDM $04` | MACRD | reads the total: low half in `A`, high half in `Y` |
| `WDM $05` | MACCLR | sets the total to 0 |
| `WDM $06` | MULS | `Y:A = A * X`, signed |
| `WDM $07` | DIVS | signed `A / X`; `Y` = remainder, with the sign of `A` |
| `WDM $08` | MACS | adds the signed product `A * X` to the total |
| `WDM $09` | MACLD | writes the total from `Y` (high half) and `A` (low half) |

`WDM $02` and `WDM $07` take 11 processor cycles. The other operations take 2.

`DIVS` rounds toward 0. It sets V = 1 for a division by 0 and for -32768 / -1. A division by 0 gives `A` = `$FFFF` and `Y` = old `A`.

The register `$5F03` gives the version of the set. The value `$02` means the operations of the table. In an interrupt handler, save the total with `MACRD` and restore it with `MACLD`.

::: warn
Use the extensions with a 16-bit accumulator and 16-bit index registers.
:::

## Try it step by step

::: try
**1.** Switch to native mode with `CLC` and `XCE`.

**2.** Write 2 to `$5F01` with an 8-bit accumulator.

**3.** Select 16 bits with `REP #$30`.

**4.** Load `A` with `$1234` and `X` with `$0010`.

**5.** Use `WDM $01`. You must get `A` = `$2340` and `Y` = `$0001`.

:::

# Use the extensions in a game

An original game does not use `WDM`. Thus it runs as before. To use an extension, change the code of the game. This chapter shows each change: first the original code, then the modified code.

## Rules of a change

- Call `ext_on` one time, after the processor is in native mode.
- Change the inside of a routine. Keep its name, its inputs, and its outputs. Thus the callers do not change.
- Keep the original lines in the routine if the game must also run on an original console.
- Call the modified routines in native mode only.
- The data bank must be in `$00-$3F` or `$80-$BF`. The registers `$42xx` and `$5Fxx` are visible there.
- The examples need the decimal flag at 0.
- `ext_on` writes its flag to the byte `$00F0`. In your game, choose a byte that is free.
- The addresses of the inputs and outputs are examples. Use the addresses of your game.

## What you get

| Task | Original | Modified |
|---|---|---|
| multiply 16 x 16 bits | 192 cycles | 62 cycles |
| multiply 16 x 16 bits, signed | 230 to 262 cycles | 62 cycles |
| divide 16 / 8 bits | 80 cycles | 76 cycles |
| sum of 3 products | 767 cycles | 90 cycles |

The numbers are processor cycles in the simulation, from the call to the return. The modified routines also save `X` and `Y`. Both versions gave equal results in 60 runs with random numbers.

## Turn the extensions on

### Original code

```
reset:  CLC
        XCE                 ; native mode
        ; ... the game ...
```

### Modified code

::: copy
reset:  CLC
        XCE                 ; native mode
        JSR ext_on          ; the new line
        ; ... the game ...
:::

### New routine

::: copy
ext_on: PHP
        SEP #$20
        LDA #$00
        STA $00F0           ; 0: no extensions
        LDA $5F00
        CMP #$58            ; the identifier
        BNE ext_x
        LDA $5F03
        CMP #$02            ; all 9 operations
        BCC ext_x
        LDA #$02
        STA $5F01           ; extended mode on
        LDA #$01
        STA $00F0           ; 1: extensions ready
ext_x:  PLP
        RTS
:::

::: warn
On an original console, `WDM` does nothing. A modified routine without the original lines gives wrong results there. The reading of `$5F00` on an original console was not tried.
:::

## Multiply 16 x 16 bits

The inputs are the words `$0010` and `$0012`. The 32-bit result goes to `$0020-$0023`. The original code makes four 8 x 8 products with the 5A22.

### Original code

```

        LDA $0010           ; a low
        STA $4202
        LDA $0012           ; b low
        STA $4203
        NOP                 ; NOP, REP, LDA: 8 cycles
        REP #$20
        LDA $4216
        STA $0020
        SEP #$20
        LDA $0011           ; a high
        STA $4202
        LDA $0013           ; b high
        STA $4203
        NOP
        REP #$20
        LDA $4216
        STA $0022
        SEP #$20
        LDA $0010           ; a low x b high
        STA $4202
        LDA $0013
        STA $4203
        NOP
        REP #$20
        LDA $4216
        CLC
        ADC $0021
        STA $0021
        SEP #$20
        LDA $0023
        ADC #$00
        STA $0023
        LDA $0011           ; a high x b low
        STA $4202
        LDA $0012
        STA $4203
        NOP
        REP #$20
        LDA $4216
        CLC
        ADC $0021
        STA $0021
        SEP #$20

        STA $0023

        RTS
```

This routine uses the extension if `ext_on` found it. If not, it runs the original lines. It took 71 cycles with the extension and 199 cycles without it.

mul16:  PHP
        SEP #$20

## Divide

The dividend is the word `$0010`. The divisor is the byte `$0012`. The quotient goes to `$0020` and the remainder to `$0022`.

### Original code

```
div:    PHP
        REP #$20
        LDA $0010           ; 16-bit dividend
        STA $4204
        SEP #$20
        LDA $0012           ; 8-bit divisor
        STA $4206
        NOP
        NOP
        NOP
        NOP
        NOP
        NOP
        NOP                 ; 7 NOP, REP, LDA: 20 cycles
        REP #$20
        LDA $4214
        STA $0020           ; quotient
        LDA $4216
        STA $0022           ; remainder
        PLP
        RTS
```

### Modified code

::: copy
div:    PHP
        REP #$30
        PHX
        PHY
        LDA $0012
        AND #$00FF          ; the same 8-bit divisor
        TAX
        LDA $0010
        WDM $02             ; A = quotient, Y = remainder
        STA $0020
        STY $0022
        PLY
        PLX
        PLP
        RTS
:::

The gain is small here, because the 5A22 already has a divider. For a 16-bit divisor, replace `LDA`, `AND`, and `TAX` with `LDX $0012`. The 5A22 cannot do that division.

For signed numbers, use `WDM $07` with 16-bit inputs.

## Sum of products

The routine adds three products. The first factors are the words `$0040`, `$0042`, and `$0044`. The second factors are `$0046`, `$0048`, and `$004A`. The 32-bit total goes to `$0030-$0033`.

### Original code

```
dot3:   PHP
        REP #$20
        LDA #$0000
        STA $0030           ; total, low word
        STA $0032           ; total, high word
        LDA $0040
        STA $0010
        LDA $0046
        STA $0012
        JSR mul16
        LDA $0030
        CLC
        ADC $0020
        STA $0030
        LDA $0032
        ADC $0022
        STA $0032
        ; the same 12 lines with $0042 and $0048,
        ; then with $0044 and $004A
        PLP
        RTS
```

### Modified code

::: copy
dot3:   PHP
        REP #$30
        PHX
        PHY
        WDM $05             ; total = 0
        LDA $0040
        LDX $0046
        WDM $03             ; total = total + A * X
        LDA $0042
        LDX $0048
        WDM $03
        LDA $0044
        LDX $004A
        WDM $03
        WDM $04             ; A = low, Y = high
        STA $0030
        STY $0032
        PLY
        PLX
        PLP
        RTS
:::

For signed numbers, use `WDM $08` in place of `WDM $03`.

## Interrupt handler that uses the total

A handler that uses `MAC` must save the total of the program and write it back.

### Original code

```
nmi:    REP #$30
        PHA
        PHX
        PHY
        ; ... the work of the handler ...
        PLY
        PLX
        PLA
        RTI
```

### Modified code

::: copy
nmi:    REP #$30
        PHA
        PHX
        PHY
        WDM $04             ; read the total
        PHA
        PHY
        ; ... the work of the handler ...
        PLY
        PLA
        WDM $09             ; write the total back
        PLY
        PLX

        RTI

# Write a program

`sim/asm.py` is a small assembler. It knows only a small part of the instructions of the chapter "The processor": the rules below show what it accepts. It makes a 64 KB image of bank 0.

## Rules of the assembler

- Code starts at `$8000`. Use `.org` to move.
- A label ends with a colon. A comment starts with `;`.
- `LDA` and `STA` accept immediate (`LDA` only), absolute, `,X`, and long addresses.
- `ADC`, `SBC`, and `CMP` accept immediate and absolute values. `AND`, `ORA`, and `EOR` accept only immediate values.
- `LDX` and `LDY` accept immediate and absolute values. `STX` and `STY` accept absolute addresses.
- The assembler does not know the direct page, indirect, and stack relative modes.
- `.byte` and `.word` write data.
- A number starts with `$` (hexadecimal) or is decimal.
- The size of an immediate value follows the last `REP` or `SEP` above it in the file.
- For `LDA` and `STA`, a hexadecimal address with more than 4 digits gives a long address.
- Set the start address at `$FFFC`.

::: warn
An address with `,X` is always 16 bits. The assembler drops the bank of `STA $7E0100,X`.
:::

## Assemble a file

1. Save your program as `my.asm`. Start from the box below.
2. Run the command of the second box. The assembler prints the name of the output file and your labels.

::: copy
        .org $8000
reset:  CLC
        XCE
done:   BRA done

        .org $FFFC
        .word reset
:::

::: copy
python3 sim/asm.py my.asm my.hex
:::

## How much logic the full machine needs

Numbers without "measured" are estimates (about 30%).

### The original SNES, without extensions

| Block | LUT4 | Kind |
|---|---|---|
| 65C816 processor (the module holds the extensions too) | 3,200 | measured |
| 5A22: DMA and math | 1,600 | measured |
| 5A22: HDMA, video interrupts, controller ports | 1,300 | estimate |
| PPU: timing, registers, memories | 800 | measured |
| PPU: backgrounds, sprites, effects | 9,000 | estimate |
| Audio: SPC700 and DSP | 7,000 | estimate |
| Memories, cartridge, SDRAM controller | 2,600 | estimate |
| Video output | 1,000 | estimate |
| **Total** | **about 26,500 (32% of the 85F)** | |

The chips of some cartridges (SA-1, Super FX, DSP-1, and others) add about 15,000-20,000 LUT4.

### The enhanced machine without compromises

| Addition | LUT4 |
|---|---|
| Original system | 26,500 |
| Second processor | 3,500 |
| All extensions: R0-R7, vector operations, prefetch, caches, 32-bit mode, FPU | 16,000 |
| Full PPU+ with 2 copy engines | 31,000 |
| 16 audio voices with reverb | 5,500 |
| Start, SD card, keyboard, network link | 2,500 |
| **Total** | **about 85,000 (about 100%)** |

- Plan for 85% of the FPGA as the practical limit: about 71,000 LUT4.
- Without the 32-bit mode (5,000), the FPU (4,000), and the data cache (2,600): about 73,000 (87%).
- Load the cartridge chips as an alternative bitstream.
- On the Certus-N2 CT20 (future target), the full machine takes about 63% of the logic. Its tools need a paid license, and its board was not on sale on 2026-11-28.
